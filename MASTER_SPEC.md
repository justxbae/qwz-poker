# Weez Poker — Мастер-спецификация

Этот документ описывает **всю логику продукта**: пользовательские сценарии, игровую механику, экономику, платежи, бонусы, антифрод и администрирование. Является главным источником истины при конфликте других документов.

Последнее обновление: 2026-07-11

---

## 0. Принципы проекта

1. **Деньги не теряются.** Любое движение средств проходит через `ledger_entries` в одной транзакции с изменением баланса. Прямое обновление `wallets` в обход ledger запрещено.
2. **Идемпотентность.** Каждый денежный эндпойнт принимает `X-Idempotency-Key`. Повторный запрос с тем же ключом возвращает сохранённый ответ, не списывает дважды.
3. **Доверие строится на прозрачности.** Каждый игрок видит историю операций, тип баланса и механику вагеринга без скрытых условий.
4. **Play и Real — разные миры.** Нельзя перемешивать `play chips` и `real chips` ни в UI, ни в логике, ни в БД.
5. **Все данные сверяются.** Каждый час автоматическая сверка: `sum(wallets) + sum(stacks) + sum(escrow)` должна соответствовать `ledger_credits - ledger_debits`.

## 1. Единицы измерения и валютная модель

### 1.1. Баланс — это всегда USDT

**Баланс игрока = USDT.** Никакой промежуточной конвертации в «фишки» нет.

В UI и на столах отображается напрямую:
```
Стек игрока:  $14.50
Блайнды:      $0.05 / $0.10
Пот:          $1.25
```

Именно так работают TON Poker, CoinPoker и другие реальные криптопокер-румы.

### 1.2. Внутренняя единица хранения (micros)

База данных хранит балансы в **USDT micros** (`cash_usdt_micros`) для точности без float-ошибок:
```
1 USDT = 1 000 000 micros
$0.05  = 50 000 micros
$14.50 = 14 500 000 micros
```

Это технический детайл — игрок всегда видит USDT, никогда micros.

### 1.3. Stars → USDT (только платёжный курс)

Stars — один из способов оплаты депозита. Курс конвертации при депозите:
```
100 Stars = $1.00 USDT  (безопасный курс с запасом)
```

После зачисления депозита Stars исчезают из логики — баланс становится USDT.

Курс хранится в `economy_config` (`STARS_USDT_RATE`) и меняется без деплоя.

### 1.4. Play Chips — полностью отдельная единица

`play_chips_balance` хранится отдельно от `cash_usdt_micros`. Обмен невозможен в любую сторону. Play chips:
- выдаются системой бесплатно (ежедневный бонус);
- не выводятся;
- не конвертируются в USDT;
- используются только в рейтинговом режиме.

## 3. Пользовательские сценарии (User Flows)

### 3.1. Первый запуск — новый игрок

```
1. Открыл Mini App через Telegram бота
2. HMAC initData проверяется на сервере → создаётся app_user + telegram identity
3. Показывается экран выбора режима:
   - "Играть бесплатно" (Play mode)
   - "Играть на деньги" (Real mode)
4. По умолчанию открывается Главная в Play mode
5. Показывается кнопка "Получить бесплатные chips" (если ещё не получал сегодня)
6. После клейма — таймер 24 ч до следующей выдачи
7. Игрок видит список play-столов → выбирает → Buy-in modal → игра
```

**Правила выдачи play chips:**
- 35 000 play chips раз в 24 часа (единый источник значения: `ECONOMY.play.dailyRefillChips`).
- Claim доступен только при текущем play-балансе не выше 34 999 фишек и после истечения cooldown последнего успешного claim.
- До истечения cooldown кнопка показывает server-driven таймер; после истечения снова становится активной.
- Логика анти-злоупотребления: один claim на `app_user_id` в сутки и серверная проверка порога баланса внутри той же транзакции (не по IP/device).

### 3.2. Первый запуск — новый игрок с депозитом

```
1. Первый запуск → выбрал Real mode
2. Видит баланс: 0 chips + кнопку "Пополнить"
3. Касса → вводит сумму → выбирает метод оплаты:
   a. Telegram Stars — активен сейчас
   b. Crypto Bot (USDT) — активен сейчас  
   c. xRocket (USDT) — активен сейчас
   d. TON — активен (если TON_PAYMENTS_ENABLED=true)
   e. USDT TRC20 — "скоро"
4. Подтверждает → платёж → webhook → chips зачислены
5. Возвращается в Главную → видит баланс → кнопка "Играть"
6. Список столов Real mode → Buy-in → игра
```

### 3.3. Возврат активного игрока

```
1. Открыл Mini App
2. Если есть активный стол с его местом → баннер "Вернуться за стол" поверх главной
3. Если нет активного стола:
   - Показывает последний режим (Real/Play) с балансом
   - Если Real balance > 0 → "Играть"
   - Если Real balance = 0 → "Пополнить и играть" + ссылка на Play mode
```

### 3.4. Вход за стол (Buy-in flow)

```
1. Игрок выбирает стол из лобби
2. Открывается Buy-in modal:
   - Показывает: лимит стола, тип (Real/Play), мин/макс buy-in
   - Показывает доступный баланс (нужного типа)
   - Поле ввода суммы + ползунок + пресеты (Min / 50% / Max)
3. Если баланс < min buy-in → кнопка "Пополнить" вместо "Сесть"
4. Нажал "Сесть за стол" → chips списываются с wallet в table_stack
5. Если стол ещё не начал раздачу → ждёт второго игрока
6. Если уже идёт раздача → садится наблюдателем, войдёт со следующей руки
```

**Правило сохранённого стека (`saved_stacks`):**
- При уходе со стола: стек сохраняется в `saved_stacks`, не зачисляется автоматически на wallet.
- Игрок видит сохранённый стек в профиле/кассе.
- Зачисление на wallet — по кнопке "Забрать со стола" или автоматически через 7 дней неактивности.
- Это предотвращает зависшие фишки при дисконнекте.

### 3.5. Вывод средств

```
1. Касса → раздел "Вывод"
2. Видит: доступно к выводу (real balance), pending withdrawals, history
3. Вводит сумму → выбирает метод → вводит реквизиты
4. Система проверяет: KYC уровень, risk score, min withdrawal, дневной лимит
5. Если проверки прошли → статус "pending" → funds перемещаются в locked_usdt_micros
6. Ручная проверка администратором
7. Одобрено → статус "approved" → выплата → статус "paid"
   Отклонено → статус "rejected" → funds возвращаются в cash_usdt_micros
```

## 4. Игровая механика

### 4.1. Форматы игры

| Формат | Описание | Статус |
|---|---|---|
| Cash tables, 6-max | Стандартный кэш, до 6 игроков | ✅ Работает |
| Cash tables, HU | Heads-up, 2 игрока | Фаза 2 |
| SNG (Sit & Go) | Турнир, запускается при заполнении | Фаза 2 |
| MTT | Multi-table tournament с расписанием | Фаза 2 |
| Freeroll | Турнир с нулевым buy-in | Фаза 2 |
| Spin & Go | Лотерейный HU с рандомным prize pool | Фаза 3 |
| Private table | Приватный стол по коду | Фаза 2 |

### 4.2. Texas Hold'em — полные правила обработки

#### Инициализация стола

```
Минимум для старта раздачи: 2 игрока с положительным стеком.
Максимум игроков: 6.
Позиции: UTG, HJ, CO, BTN, SB, BB (6-max naming).
Dealer button вращается по часовой стрелке при каждой руке.
```

#### Последовательность раздачи

```
1. DEAL: каждому игроку 2 карманные карты (face down)
2. PREFLOP: SB платит малый блайнд, BB платит большой блайнд
   Порядок действий: UTG → HJ → CO → BTN → SB → BB
3. FLOP: 3 общие карты открываются
   Порядок действий: SB → BB → UTG → ... → BTN
4. TURN: 4-я общая карта
   Порядок действий: тот же, что flop
5. RIVER: 5-я общая карта
   Порядок действий: тот же
6. SHOWDOWN: игроки показывают карты
7. PAYOUT: победитель(и) получают пот(ы), вычитается рейк
```

#### Действия игрока

| Действие | Условие |
|---|---|
| Fold | Всегда доступно |
| Check | Нет активной ставки на этом круге |
| Call | Есть активная ставка, у игрока достаточно стека |
| Call (partial) | Есть активная ставка, стек меньше ставки → all-in |
| Bet | Нет активной ставки, min = 1 BB |
| Raise | Есть активная ставка, min raise = предыдущий raise или 2x call |
| All-in | Всегда доступно, если у игрока > 0 в стеке |

#### Таймеры

| Событие | Таймаут | Поведение |
|---|---|---|
| Ход игрока | 20 секунд | Auto-check, если check доступен; иначе auto-fold |
| Ход игрока (timebank) | +15 сек | Резерв для следующей итерации UI/UX; серверный контракт должен оставаться конфигурируемым |
| Ожидание начала | 120 сек | Если второй игрок не пришёл — стол закрывается, buy-in возвращается |
| Tournament reconnect window | 30 сек | Только для турниров: место не освобождается, игрок продолжает blind/ante out |

#### Side Pots

```
Side pot создаётся, когда игрок идёт all-in на сумму меньше текущей ставки.

Пример:
- Игрок A: стек 1000, ставит all-in 1000
- Игрок B: стек 2000, коллирует
- Игрок C: стек 3000, рейзит до 3000

Поты:
- Main pot: 3000 (A × 1000 + B × 1000 + C × 1000) — разыгрывают A, B, C
- Side pot 1: 2000 (B × 1000 + C × 1000) — разыгрывают B, C
- Side pot 2: 1000 (C × 1000 только) — возвращается C автоматически

Рейк снимается с каждого пота отдельно по формуле.
```

#### Showdown правила

```
Showdown обязателен, если дошли до river с несколькими активными игроками.
Порядок показа карт: последний aggressor показывает первым, затем по часовой.
Muck: если игрок проигрывает — может не показывать карты (кроме случаев all-in runout).
All-in runout: ВСЕ карты показываются обоим игрокам, никаких mucked hands.
```

#### Post-hand окно: show / muck

```
После обычного showdown сервер открывает короткое post-hand окно show/muck.

Правила:
1. Игрок, имеющий право показать или скрыть проигравшую руку, получает отдельное server-driven окно решения.
2. Default deadline окна — `3 000 ms`; клиент получает абсолютный server deadline.
3. Если игрок ничего не выбрал за отведённое время, применяется auto-muck.
4. Победитель раскрывается автоматически; all-in runout раскрывает все не сброшенные руки и не открывает окно.
5. Визуальный muck не раскрывает карты на столе. Участникам завершённой руки hand history показывает не сброшенные showdown-руки; folded-facing-bet карты другим игрокам не раскрываются.
6. Результат show/muck логируется в hand history и table events.
7. Следующая рука не стартует до закрытия окна.
```

Rabbit Hunt не входит в beta++/первый публичный запуск. Это не базовое правило Hold'em,
а отдельная опциональная функция рума, влияющая на темп следующей раздачи, раскрытие
дополнительной информации, UX и денежный ledger. До отдельного продуктового ТЗ сервер не
предлагает Rabbit Hunt, не списывает за него средства и не публикует его события.

#### Дисконнект и sit-out

```
Cash/rating:
1. Если игрок закрыл приложение или потерял соединение, но сейчас не его ход,
   сервер не показывает отдельный reconnect-state и не меняет ход раздачи.
2. Когда очередь доходит до отсутствующего игрока, действует обычный action timer.
3. По истечении таймера:
   - если check доступен → auto-check;
   - если нужно отвечать на ставку → auto-fold.
4. После timeout отсутствующий игрок получает sit-out со следующей руки
   или сразу после fold, если его участие в руке завершено.
5. Sit-out длится 300 секунд. В cash/rating игрок в sit-out не получает карты
   и ему не ставятся новые small/big blind.
6. Если за 300 секунд игрок не вернулся, сервер автоматически освобождает место:
   - cash stack возвращается в cash_usdt_micros через ledger;
   - play stack возвращается в PLAY_CHIPS wallet;
   - active session удаляется.

Tournament:
1. Игрок не удаляется из турнира из-за disconnect/sit-out.
2. Blinds/antes продолжают списываться с турнирного стека.
3. На ходе применяется auto-check, если check доступен, иначе auto-fold.
4. Игрок выбывает только по обычным tournament/bust правилам.
```

### 4.3. Рейк — полная формула

#### Кэш-игры

```
Базовая формула:
  rake_amount = min(floor(pot × rake_rate), cap_in_bb × big_blind)

Условие no-flop-no-drop:
  if (board_cards < 3) → rake = 0

Расчёт по стейкам:
  Micro (25/50, 50/100):        rake_rate = 5%,  cap = 3 BB
  Low  (100/200, 500/1000):     rake_rate = 5%,  cap = 2.5 BB
  Mid  (1000/2000, 5000/10000): rake_rate = 4%,  cap = 2 BB
  High (25000/50000+):          rake_rate = 2.5%, cap = 1.5 BB
  HU (любой стейк):             rake_rate = 5%,  cap = 2 BB
```

#### Weighted Contributed Rake (WCR) для VIP-учёта

```
Для расчёта playerRakePaid (нужно для VPP и рейкбека):
  player_rake_share = (player_total_bet / pot) × total_rake

Это не влияет на сумму, идущую клубу — только на распределение VPP.
```

#### Турнирный fee

```
Структура "buy-in + fee":
  buy-in → идёт в prize pool
  fee    → доход клуба

  Micro freeroll: 0 + 0 (promo)
  Low MTT:        1 000 + 100 chips (10%)
  Mid MTT:        10 000 + 700 chips (7%)
  High MTT:       50 000 + 2 500 chips (5%)
  High-roller:    250 000 + 7 500 chips (3%)
  Satellite:      1 000 + 200 chips (20% — приз стоит дороже)

Re-entry fee = такой же fee за каждый re-entry.
```

## 5. Платёжная система

### 5.1. Методы пополнения

| Метод | Статус | Комиссия Telegram/провайдера | Рекомендация UX |
|---|---|---|---|
| Telegram Stars | ✅ Активен | ~30% от Stars-суммы | Для малых депозитов, быстрый onboarding |
| Crypto Bot (USDT) | ✅ Активен | ~0.5% | Для крипто-пользователей |
| xRocket (USDT) | ✅ Активен | ~0.5% | Альтернатива Crypto Bot |

### 5.2. Флоу пополнения (единый)

```
1. Клиент запрашивает инвойс: POST /api/cashier/[method]-order
   - Тело: { amount_usdt, idempotency_key }
2. Бэкенд создаёт payment_order:
   { status: 'pending', method, amount_usdt, user_id, expires_at: +30 мин }
3. Бэкенд создаёт инвойс у провайдера (Stars: createInvoiceLink, CryptoBot: createInvoice)
4. Клиент перенаправляется на оплату (Stars: Telegram native payment, крипта: провайдер mini app)
5. Провайдер присылает webhook (подпись проверяется):
   { orderId, status: 'paid'/'confirmed', txHash/paidAmount }
6. Webhook handler в одной PostgreSQL транзакции:
   - payment_orders.status = 'paid'
   - wallets.cash_usdt_micros += credited_amount
   - ledger_entries.insert(type='credit', category='deposit_[method]')
   - analytics_events.insert('deposit_paid')
7. Клиент получает realtime-обновление (SSE/push): "Баланс пополнен: +X chips"
```

**Критические правила:**
- Никогда не кредитовать chips по client-callback. Только по подтверждённому webhook.
- Повторный webhook с тем же `orderId` игнорируется (idempotency на payment_orders).
- Недоплата (paid < expected): статус `manual_review`, chips не зачисляются.
- Истёкший ордер (>30 мин без оплаты): статус `expired`, chips не зачисляются.

### 5.3. Конвертация Stars → USDT

```
Текущий курс: 1000 Stars = 10 USDT
Это бизнес-параметр, не константа кода.
Хранится в: economy_config.stars_usdt_rate

Проверка маржи:
  Рыночная стоимость 1000 Stars на Fragment ≈ $12.75–$15.00
  После реализации Stars клуб ориентировочно получает ≈ $10.84–$12.75
  Мы засчитываем $10.00 → запас ≈ $0.84–$2.75 покрывает комиссии и волатильность
  Поэтому Stars — для малых депозитов, крипта — для крупных.
```

### 5.5. Вывод средств — полный флоу

```
1. Игрок запрашивает вывод в UI: касса → вывод → сумма + метод + реквизиты
2. Бэкенд проверяет:
   a. KYC tier соответствует сумме вывода
   b. Risk score игрока (yellow/orange/red — требует manual)
   c. Min withdrawal threshold
   d. Wagering: real_balance - bonus_origin_amount должно быть ≥ 0
      (нельзя вывести "незаработанный" бонус)
   e. Velocity: нет подозрительного паттерна (deposit → immediate withdrawal)
3. Если всё ок → withdrawal_request создаётся со статусом 'pending'
4. chips перемещаются: cash_usdt_micros → locked_usdt_micros
5. Игрок видит: "Заявка принята, ожидает проверки"
6. Администратор в панели видит withdrawal queue:
   - Игрок, сумма, метод, реквизиты, risk flags, история депозитов/игры
7. Admin одобряет → провайдер получает запрос на выплату → статус 'approved' → 'paid'
   Admin отклоняет → chips возвращаются в cash_usdt_micros → статус 'rejected'
8. Игрок получает push-уведомление о статусе
```

**Комиссии при выводе:**

|---|---|---|---|

| USDT (CryptoBot/xRocket) | 4% + 1 USDT сеть | 50 000 chips | 1 000 000 chips |
| USDT TRC20 | 4% + 1 USDT сеть | 50 000 chips | 1 000 000 chips |
| Stars Gifts | 12% | 25 000 chips | 100 000 chips |

На старте (Фаза 1) вывод работает только в ручном режиме.

## 6. Баланс — три типа средств

### 6.1. Cash Balance (`cash_usdt_micros`)

- Реальные деньги. Можно вывести (при соблюдении условий).
- Пополняется депозитами и выигрышами (рейк не включён в "выигрыш").
- Используется для Real mode столов.

### 6.2. Bonus Balance (`bonus_usdt_micros`)

- Бонусные средства с вагерингом. Не выводятся напрямую.
- При выполнении условий вагеринга конвертируются в `cash_usdt_micros` по 1:1.
- Отображаются как "Бонус: X chips (отыграно Y из Z)".
- Могут быть ограничены для определённых стейков.

### 6.3. Play Chips (`play_chips_balance`)

- Бесплатные фантики. Никогда не конвертируются в реальные деньги.
- Отдельный balance, полностью изолированный от cash и bonus.
- Пополняются ежедневно по клейму.
- Могут пополняться ещё через: ачивменты, freeroll-призы, реферальные бонусы (в play mode).

### 6.4. Правило отображения в UI

```
Показывать три строки в балансе:
  ✅ Real chips:  12 500    (выводимые)
  🎁 Bonus chips: 5 000     (нужно отыграть 3 000 рейка)
  🎮 Play chips:  8 200     (бесплатно)

Кнопка "Вывести" активна только рядом с Real chips.
Кнопка "Как получить?" рядом с Bonus chips открывает условия вагеринга.
```

## 7. Бонусная система

### 7.1. Welcome Bonus (первый депозит)

```
Условия:
  - Первый депозит ≥ 2 500 chips
  - Один welcome на: Telegram ID + устройство + IP (проверяется при активации)
  - Автоматически активируется при первом депозите

Структура:
  - Бонус: 100% от суммы первого депозита, максимум 5 000 chips
  - Срок: 30 дней на отыгрыш
  - Вагеринг: нужно сыграть рейк = bonus_amount × 1.0

Механика отыгрыша:
  - Каждый chip сыгранного рейка освобождает 1 chip бонуса
  - Освобождённые chips немедленно переходят в cash_usdt_micros
  - Пример: получил 5 000 бонус → сыграл 2 000 рейка → 2 000 из бонуса стали cash
  - По истечении 30 дней: неотыгранный остаток сгорает

Ограничения вагеринга:
  - Кэш столы всех стейков: 100% зачёт рейка
  - Турнирные fee: 50% зачёт
  - Play chips столы: 0% зачёт (бонус не отыгрывается на фантиках)
```

### 7.2. Reload Bonus (повторные депозиты)

```
  - 50% на 2-й и 3-й депозит, максимум 2 500 chips каждый
  - Активируется только промокодом (не автоматически) → защита от абуза
  - Тот же вагеринг × 1.0, срок 30 дней
  - Промокод получается: в Telegram-боте, из рассылки, у реферера
```

### 7.3. Daily / Weekly Missions

Бюджет: 5% от net rake за период.

| Миссия | Награда | Период | Тип |
|---|---|---|---|
| Сыграй 50 рук | 200 chips | Daily | Engagement |
| Дойди до showdown 10 раз | 300 chips | Daily | Анти-фолд |
| Сыграй на 2+ столах одновременно | 500 chips | Daily | Multi-tabling |
| Сделай 3 successful bluff (оппонент фолднул на river bet) | 400 chips | Daily | Skill recognition |
| Зарегистрируйся в 3 турнирах | 1 000 chips | Weekly | Tournament adoption |
| Заработай 100 chips VPP | 500 chips | Weekly | VIP-активация |
| Сыграй 500 рук за неделю | 2 000 chips | Weekly | Activity |
| Пополни баланс впервые этим месяцем | 1 000 chips | Monthly | Retention |

Награды за миссии — **прямое зачисление в cash_usdt_micros** (без вагеринга).

### 7.4. Ежедневные Freerolls

| Событие | Периодичность | Prize pool | Условие участия |
|---|---|---|---|
| Micro Daily | Каждый день 20:00 MSK | 5 000 chips | Любой пользователь |
| Weekly | Каждое воскресенье 18:00 | 50 000 chips | D7+ (был активен 7+ дней) |
| Monthly Major | 1-е число каждого месяца | 500 000 chips | Был депозит ≥ 2 500 chips |

Призы freeroll → cash_usdt_micros (без вагеринга). Это ключевое отличие от бонуса.

### 7.5. Bad Beat Jackpot (BBJ)

```
Источник пула:
  1% от рейка на каждой раздаче с флопом + шоудауном → bbj_pool

Минимальный seed: 10 000 chips (клуб пополняет после каждой выплаты)

Триггер:
  - Проигравший имеет: Quads (четыре карты) JJJJ или выше
  - Условие: используются ОБЕ карманные карты
  - Проигрывает стрит-флешу или старшему каре

Распределение при выплате:
  50% — проигравший (bad beat hero)
  30% — победитель руки
  20% — остальные игроки, получившие карты за этим столом

После выплаты:
  - Пул обнуляется
  - Seed 10 000 chips зачисляется в bbj_pool немедленно
  - На главном экране отображается текущий размер BBJ

Бюджетный cap на BBJ:
  bbj_pool не может превышать 5% от monthly net rake × 12 (то есть 5% от LTM rake)
  При достижении — контрибуция в пул останавливается, но пул не сгорает.
```

### 7.6. VIP / Loyalty Program

#### Начисление VPP

```
1 VPP = за каждые 100 chips сыгранного рейка (по WCR-методу)
Например: сыграл 500 chips рейка → получил 5 VPP

VPP накапливаются rolling 30 дней (не календарный месяц).
VPP за пределами 30-дневного окна сгорают для расчёта уровня.
```

#### Уровни и привилегии

| Уровень | VPP за 30 дней | Рейкбек | Дополнительно |
|---|---|---|---|
| Bronze | 0 – 999 | 5% | — |
| Silver | 1 000 – 4 999 | 10% | Доступ к VIP-freerolls |
| Gold | 5 000 – 19 999 | 15% | Ускоренные выводы (приоритет в очереди) |
| Platinum | 20 000 – 99 999 | 22% | Personal manager в Telegram |
| Diamond | 100 000+ | 30% | Спецтурниры, обмен VPP на Telegram-gifts |

#### Механика рейкбека

```
Рейкбек начисляется еженедельно в воскресенье в 00:00 UTC.
Расчёт: player_rake_paid_last_7_days × current_rakeback_rate
Зачисляется в cash_usdt_micros (без вагеринга).
Записывается в ledger с category='rakeback'.
```

### 7.7. Бонусный бюджет — жёсткий cap

```
Лимит: сумма всех активных promo_grants ≤ 25% от net rake за последние 30 дней.

При достижении лимита:
  - Daily missions: продолжают работать (малый бюджет, высокий retention ROI)
  - Welcome/reload bonus: продолжают активироваться (уже "продали" игроку)
  - Freerolls: автопауза до следующего расчётного периода
  - BBJ: продолжает накапливаться (это не прямой расход, это redistribution)
  - Новые reload промокоды: не генерируются

Admin видит в панели: "Бонусный бюджет: используется X% от лимита (Y chips из Z chips)"
```

## 8. Реферальная программа

### 8.1. Атрибуция

```
1. Рефер создаёт ссылку: t.me/qwzpokerbot?start=ref_ABCD1234
2. Новый пользователь открывает по ссылке → start_param сохраняется при первом /api/auth
3. Запись в referrals: { referrer_id, referred_id, code, source, created_at }
4. Атрибуция считается "валидной" после FTD (First-Time Deposit):
   - Минимум: депозит ≥ 2 500 chips + сыгранный рейк ≥ 500 chips
5. Без FTD → рефер не зарабатывает ничего (защита от фейковых регистраций)
```

### 8.2. Модели монетизации

**Revenue Share (RevShare) — основная:**

| Уровень | Критерий | % net rake реферала | Срок | Sub-affiliate |
|---|---|---|---|---|
| Junior | 0–9 активных рефералов | 25% | 12 мес | — |
| Senior | 10–49 активных | 30% | 12 мес | 3% от суб-рефералов |
| Elite | 50+ активных | 35% | Lifetime | 5% от суб-рефералов |
| Stream/VIP | Индивидуально | до 45% | Индивидуально | 5–7% |

*"Активный реферал" = сыграл рейк в текущем месяце.*

**CPA (Cost-Per-Acquisition) — альтернативная:**
- $20 (≈ 1 500 chips) за валидного игрока (FTD ≥ 2 500 chips + ≥ 500 chips рейка)
- $50 (≈ 3 750 chips) за VIP (FTD ≥ 50 000 chips + ≥ 5 000 chips рейка)

Модель выбирается при подключении партнёрки. Гибрид (CPA + 10% RevShare) — для крупных.

### 8.3. Расчёт и выплата

```
Net rake реферала = рейк реферала – рейкбек реферала – бонусные промо реферала

Выплата:
  - Раз в месяц, 1-го числа
  - Зачисляется в cash_usdt_micros реферера
  - Min: 5 000 chips для выплаты (иначе накапливается)
  - Реферер видит pending balance в реальном времени
```

### 8.4. Анти-абуз реферальной системы

| Атака | Защита |
|---|---|
| Self-referral | Device fingerprint + IP + Telegram ID на обоих аккаунтах |
| Бонус-фарминг | RevShare только с реально сыгранного рейка, не с депозита |
| Chip-dumping рефер→реферал | Win/loss матрица, флаг при дисбалансе |
| Кольцо (A→B→C→A) | Граф взаимных рефералов сканируется ежедневно |

## 12. Провабли-фэйр (Честность раздач)

### 12.1. Схема Commit–Reveal

```
1. До начала руки:
   - Сервер генерирует serverSeed (32 байта CSPRNG)
   - Публикует commit = sha256(serverSeed) — виден игрокам
   - Игрок может задать playerSeed до начала руки (опционально)

2. Тасование колоды:
   - combinedSeed = sha256(serverSeed + playerSeeds + handNumber + tableId)
   - Колода тасуется детерминированно Fisher-Yates из combinedSeed

3. После завершения руки:
   - serverSeed раскрывается публично
   - Игрок может локально воспроизвести тасовку и убедиться, что карты те же
   - Данные пишутся в hand_histories.fairness_proof

4. Проверка в UI:
   - Экран "Проверить раздачу" показывает: server hash, player hash, revealed seed
   - Кнопка "Проверить" → локальная проверка в браузере → "✅ Раздача честна"
```

### 12.2. Хранение

```
hand_histories.fairness_proof = {
  serverSeedHash: "sha256...",
  serverSeed: "revealed after hand",
  playerSeeds: [...],
  combinedSeed: "sha256...",
  handNumber: 1234,
  deckOrder: [карты в порядке тасования]
}
```

## 13. Турниры — полная механика

### 13.1. Жизненный цикл турнира

```
CREATED → REGISTRATION_OPEN → [LATE_REGISTRATION] → RUNNING → FINAL_TABLE → FINISHED
```

**CREATED:** Турнир создан в расписании. Не виден игрокам.
**REGISTRATION_OPEN:** Игроки могут регистрироваться. Chips в escrow.
**LATE_REGISTRATION:** Турнир стартовал, но ещё можно зайти (обычно 1 уровень блайндов).
**RUNNING:** Идут раздачи. Новые регистрации закрыты.
**FINAL_TABLE:** Финальный стол (9 или меньше игроков).
**FINISHED:** Разыгран призовой фонд, escrow роздан.

### 13.2. Регистрация и эскроу

```
1. Игрок регистрируется: POST /api/tournaments/:id/register
2. Проверки: достаточно chips, турнир в REGISTRATION_OPEN, игрок не зарегистрирован
3. В одной транзакции:
   - cash_usdt_micros -= (buyin + fee)
   - tournament_registrations.insert(status='active')
   - tournament_escrow += buyin (fee остаётся клубу)
   - ledger_entries.insert(type='debit', category='tournament_buyin')
   - platform_ledger_entries.insert(category='tournament_fee')
4. Отмена до старта: полный возврат buyin из escrow
5. Отмена после старта: не возможна (если не предусмотрен re-entry)
```

### 13.3. Re-entry / Rebuy / Add-on

```
Re-entry:
  - Игрок выбыл → может вернуться с новым full stack
  - Разрешён в пределах late registration window
  - Каждый re-entry = отдельный fee
  - Unlimited re-entries (по умолчанию) или с лимитом (настройка турнира)

Rebuy (только early levels):
  - Игрок с малым стеком (≤ starting_stack) может купить дополнительные chips
  - Chips добавляются к текущему стеку
  - Обычно доступен первые 6 уровней блайндов

Add-on (перерыв после ранних уровней):
  - Все игроки могут купить дополнительные chips (независимо от стека)
  - Один раз за турнир
  - По сигналу администратора (clock pause)
```

### 13.6. Реализация MVP

Backend поддерживает MTT и базовый SNG в текущем монолите. Канонический state machine: `created → registration_open → late_registration → running → final_table → finished`, с терминальным `cancelled`. SNG стартует при заполнении, MTT — по `startsAt`; при нехватке `minPlayers` регистрации возвращаются.

Обычные турниры в MVP cash-only: buy-in и payout идут только через `cash_usdt_micros`. Play chips не используются как вход в спонтанные турниры и не участвуют в tournament escrow. Турнирные игровые стеки не являются wallet balance и не участвуют в cash/play table-stack reconciliation. Re-entry, add-on, freeroll, satellites и bounty не входят в первый MVP.

### 13.7. Сезонные reward-турниры по билетам

После завершения рейтингового сезона топы leaderboard могут получать tickets на отдельные приглашённые турниры или freeroll-формат. Билет — это не валюта и не buy-in; он выдаётся админкой или системой по месту в leaderboard, а участие проходит по списку ticket holders. Эти турниры не смешиваются с обычным cash MTT/SNG runtime и описываются отдельно как post-season reward flow.

## 16. Открытые вопросы (требуют решения собственника)

1. **Юрлицо.** Curaçao с лицензией ($30k+ старт) vs оффшор без лицензии (проще, но ограничивает платёжные инструменты). Влияет на доступность gateway и возможность card-оплаты.

2. **Ставка Stars→USDT.** Production-правило: 100 Stars = 1 USDT. Курс остаётся конфигурируемым через `STARS_USDT_RATE`; изменение требует отдельного Economy decision.

3. **Welcome bonus агрессивность.** 100% match — стандарт индустрии. 200% match — сильный WoM, выше CAC. 50% match — безопасно, но теряем vs конкурентов. Решение зависит от бюджета Фазы 1.

4. **Min withdrawal: $5 vs $10.** $5 (25 000 chips) — лучше для small fish, больше операций в очереди. $10 (50 000 chips) — меньше нагрузка на ops, хуже UX.

5. **TON или USDT — приоритет для крупных.** TON дешевле в сети (~$0.05), USDT привычнее опытным крипто-игрокам. Рекомендация: оба, TON позиционируется как "быстрый и дешёвый".

6. **Вагеринг play chips.** Сейчас play chips полностью изолированы. Вопрос: давать ли play chip freeroll-призы в виде cash (маленькая сумма, высокий конверсионный эффект)? Риск — злоупотребление мульти-аккаунтами.

7. **Ограничения стека.** Max buy-in сейчас = 100 BB (стандарт). Обсудить: нужны ли deep stack столы (200 BB) — они популярны у regulars, но требуют более сложного управления банком.
