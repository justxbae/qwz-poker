# Cloudflare Workers Free

Выбор владельца от 17.10.2026: бесплатный Workers, без Containers и Render.
Адрес конфигурации: `https://weez-poker.wizzssm.workers.dev`, бот `@qwzpokerbot`.

## Что запускается

- `public/` обслуживается через Workers Static Assets.
- API и Telegram webhook проходят в один SQLite Durable Object `PokerRoom`,
  постоянный ключ `weez-room-v1`. Один владелец состояния и последовательная обработка операций.
- `server/application.js` создаёт независимый экземпляр существующего приложения.
  Node.js продолжает запускаться через `server/index.js`; API и Hold'em общие.
- HTTP-совместимость использует официальный `cloudflare:node`, без другого игрового движка.
- После запроса состояние комнаты и ближайший alarm фиксируются одной storage-транзакцией.
  Ответ операции возвращается после commit. Сохраняются профили, игровые кошельки,
  ledger, ежедневные выдачи, idempotency, сессии, столы, карты, очередь хода и дедлайны.
- Между запросами игру продолжает alarm. В пустой комнате alarms не создаются.
  В занятой комнате пробуждение — по ближайшему игровому событию, с проверкой
  присутствия/выхода не реже 10 секунд. Постоянные Node intervals отключены.
- Snapshots делятся на небольшие части; неизменные части повторно не записываются.
  Кодек сохраняет Map/Set и общие ссылки профилей/сессий. Неполное состояние
  вызывает ошибку, а не обнуление кошельков.

## Режим и границы

Это публичная PLAY-beta. Worker принудительно выключает реальные деньги,
выводы и платёжные адаптеры независимо от случайной настройки окружения.
PostgreSQL/Redis не используются; хранилище здесь — SQLite Durable Object.
Данные старого Render не импортируются и не удаляются.

Это не готовая архитектура cash-room или большого онлайна. Для реальных денег
нужны отдельная проверка transactional ledger/recovery, необходимые продуктовые
исправления из `LAUNCH_REVIEW.md` и нагрузочная приёмка. Один DO обслуживает
всю текущую комнату; разнесение по столам — следующая архитектурная задача.

Free-квоты конечны: при их превышении операции начинают отклоняться. Не включать
платный план автоматически. Метрики и исходные условия:
[Workers limits](https://developers.cloudflare.com/workers/platform/limits/),
[Durable Objects pricing](https://developers.cloudflare.com/durable-objects/platform/pricing/).

## Проверка и публикация

Приложение поддерживает Node >=20; актуальному Wrangler нужен Node >=22.

```bash
npm ci
npm ci --prefix infra/cloudflare
npm test
npm run test:cloudflare
npm exec --prefix infra/cloudflare -- wrangler deploy --dry-run
npm exec --prefix infra/cloudflare -- wrangler deploy
```

`wrangler.jsonc` содержит только публичные настройки. Через `wrangler secret bulk`
задаются `BOT_TOKEN`, `TELEGRAM_WEBHOOK_SECRET` и `METRICS_TOKEN`.
Секреты нельзя добавлять в Git или выводить в логи. `.dev.vars` — только локальная
проверка, production не получает его автоматически.

`test:cloudflare` запускает настоящий локальный workerd в отдельном временном
окружении: проверяет Telegram HMAC, отказ без авторизации, ежедневную выдачу,
два места за столом, раздачу, полный перезапуск процесса, сохранение карт/банка/
turnToken/баланса, idempotent retry и возврат фишек без потерь. Настоящий бот и
production-хранилище в этой проверке не используются.

Публиковать из `codex/cloudflare-production`, указывать `BUILD_COMMIT` опубликованного
коммита. Не пушить `main` по привычке: он всё ещё подключён к старому Render.
`/source` ведёт на соответствующий публичный исходный код; лицензии vendor сохранены.

## Переключение Telegram

Сначала подтвердить `/api/health`, `/api/config`, assets и Telegram-вход на новом URL.
Только после этого выставить webhook на новый `/api/telegram/webhook` с новым
secret_token и кнопку меню `Играть` с HTTPS URL Cloudflare. Автонастройка Telegram
при создании DO отключена: холодный запуск не должен повторно менять webhook.

Основная Mini App в профиле бота имеет отдельный URL в BotFather. Кнопка меню и
кнопка из `/start` получают новый URL через Bot API; URL основной Mini App надо
обновить отдельно, если он остался старым. Старый Render при старте может
переустановить настройки бота; после успешного переноса отключить его управление
ботом/автодеплой. Не запускать два cash-writer на одной базе.

## Обновление и откат

Не менять имя Worker, класс DO, migration `v1` или ключ `weez-room-v1`: это другое
хранилище, а не обновление приложения. Не удалять namespace для исправления ошибки.
Сначала совместимость snapshot, затем публикация. Перед изменением схемы состояния
нужны backup и миграция. Версия snapshot сейчас `1`.

Откат кода допустим только на версию, понимающую текущий snapshot; восстановление
проверяется на отдельном окружении. Страница открывается на Cloudflare HTTPS без
собственного домена. Покупка домена и платных ресурсов для этого запуска не нужна.
