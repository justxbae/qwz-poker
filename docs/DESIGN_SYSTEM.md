# Weez Design System 2.0

Статус: **канонический документ frontend-дизайна**. Он заменяет все старые визуальные договорённости, если они ему противоречат. Продуктовые и финансовые правила по-прежнему определяются `MASTER_SPEC.md` и `docs/13-decisions.md`.

## 1. Принцип

Weez — Telegram Mini App, поэтому интерфейс должен ощущаться как часть Telegram, но не притворяться нативным UIKit-приложением. Основа системы:

1. Telegram Mini Apps Theme API — источник пользовательских цветов.
2. Apple Human Interface Guidelines — источник иерархии, размеров касания, типографики и поведения sheet/navigation на iOS.
3. Локальные SVG-экспорты в `archive/design/figma/` — источник утверждённой геометрии иконок и референсов.
4. Weez — собственный игровой слой: стол, карты, игровые статусы и брендовый акцент.

Запрещено воспроизводить системные Apple/Telegram-иконки вручную через CSS, текстовые символы или псевдоэлементы, если в `archive/design/figma/` или `public/assets/` уже есть утверждённый SVG.

## 2. Источники правды

- Цвета: `Telegram.WebApp.themeParams`, затем query-параметры dev-preview, затем тёмные fallback.
- Компоненты и токены: этот документ и финально подключаемый stylesheet `public/weez-design-system-v2.css`.
- Иконки: `archive/design/figma/` → оптимизированные копии в `public/assets/`.
- Тексты и доступность действий: только API/server state.
- Денежные значения: `$` перед числом без пробела, кроме специально утверждённых русскоязычных юридических текстов.

## 3. Цветовые токены

Нельзя задавать цвет экрана или карточки напрямую в компоненте. Компоненты используют только семантические переменные:

```css
--weez-bg: var(--tg-bg);
--weez-section: var(--tg-surface);
--weez-cell: color-mix(in srgb, var(--tg-surface) 84%, var(--tg-text) 8%);
--weez-cell-pressed: color-mix(in srgb, var(--tg-surface) 76%, var(--tg-text) 14%);
--weez-text: var(--tg-text);
--weez-secondary: color-mix(in srgb, var(--tg-text) 56%, transparent);
--weez-tertiary: color-mix(in srgb, var(--tg-text) 34%, transparent);
--weez-separator: color-mix(in srgb, var(--tg-text) 14%, transparent);
--weez-accent: var(--tg-button);
--weez-accent-text: var(--tg-button-text);
--weez-danger: #ff453a;
--weez-success: #30d158;
```

Правила:

- Фон приложения — `--weez-bg` без декоративного градиента.
- Крупные секции и sheet — `--weez-section`.
- Строки, поля и вторичные овалы — `--weez-cell`.
- Контуры разрешены только там, где они передают фокус, выбор или границу игрового стола.
- Акцент пользователя берётся из Telegram. Красный, фиолетовый или синий нельзя хардкодить как активный цвет всего приложения.
- В light theme компоненты должны оставаться читаемыми; `color-scheme: dark` не должен принудительно ломать пользовательскую тему.

## 4. Типографика

Основной стек:

```css
font-family: -apple-system, BlinkMacSystemFont, "SF Pro Text", "Helvetica Neue", Arial, sans-serif;
```

Числа баланса, таймеры и короткая статистика:

```css
font-family: ui-rounded, "SF Pro Rounded", -apple-system, BlinkMacSystemFont, sans-serif;
font-variant-numeric: tabular-nums;
```

Важно: SF Pro не поставляется как webfont в репозитории. На iOS Telegram WebView используется системная SF; на Android и desktop применится системный fallback. Нельзя обещать SF Pro на каждой платформе без лицензированного webfont.

Шкала:

| Роль | Размер | Вес | Line-height |
|---|---:|---:|---:|
| Large balance | 30–40 adaptive | 600 | 1.0 |
| Screen title | 24 | 700 | 1.15 |
| Section title | 20 | 650 | 1.2 |
| Row title | 16 | 500 | 1.2 |
| Body | 15 | 400 | 1.35 |
| Secondary | 13 | 400 | 1.25 |
| Caption | 11 | 500 | 1.2 |

Использовать веса 400/500/600/700. Значения 750/800/900 запрещены для обычного интерфейса.

## 5. Сетка и геометрия

Базовый шаг — 4 px. Разрешённые отступы: 4, 8, 12, 16, 20, 24, 32.

| Элемент | Значение |
|---|---:|
| Минимальная зона касания | 44×44 |
| Стандартная строка | 52 |
| Компактная строка | 44 |
| Внутренний padding карточки | 16 |
| Gap между секциями | 16 |
| Малый радиус | 12 |
| Поле/строка | 16 |
| Карточка | 24 |
| Sheet сверху | 28 |
| Pill | 999 |

Один экран использует не более трёх радиусов: строка, карточка, pill. Овалы не должны превращаться в случайные «капсулы» разной высоты.

## 6. Базовые компоненты

### Grouped list

- Один внешний контейнер `--weez-section`, радиус 24.
- Строка 52 px, фон прозрачный.
- Иконка 40×40, внутренний SVG 22–24 px.
- Separator начинается после иконки и заканчивается до chevron.
- Chevron — только `/assets/ui/chevronright.svg`, 8×14, `--weez-tertiary`.
- Нажимается вся строка. Press отменяется, если палец ушёл за пределы или начал scroll.

### Primary button

- Высота 50–52 px, радиус 16 или pill по контексту.
- Фон `--weez-accent`, текст `--weez-accent-text`.
- Disabled: 38% opacity, без ложного pressed-state.

### Segment control

- Высота 58 px, padding 4 px, радиус 20.
- Один физический moving pill, а не смена фона двух кнопок.
- Длительность 260 ms, easing `cubic-bezier(.22,.72,.18,1)`.
- Контент экрана не должен одновременно fade-out при перемещении pill.

### Bottom navigation

- Fixed, высота 68 px, отступ 12 px + safe area.
- Фон полупрозрачный `--weez-section` с blur; без дополнительного второго фона.
- Один moving pill, который соответствует текущей вкладке.
- Контент получает нижний padding не меньше `96px + safe-area`.
- Меню сначала перемещает pill на кнопку, затем открывает sheet; при закрытии pill возвращается к активной странице.
- Никакой вибрации на переключениях.

### Sheet

- Один fixed-контейнер снизу, один backdrop, один scroll owner.
- Фон `--weez-bg`, радиус сверху 28 px.
- Grabber 36×5, виден только если sheet можно закрыть свайпом.
- При клавиатуре скроллится содержимое sheet, не лобби.
- Тап по свободному месту закрывает клавиатуру без прыжка scroll position.
- CTA находится в нормальном потоке после контента, если продукт отдельно не утвердил sticky footer.

### Money value

- `$` и целая часть — одна baseline.
- Дробная часть может быть на 30% меньше, но остаётся на baseline.
- Между `$` и числом нет пробела.
- Размер уменьшается через вычисленный `--money-scale`; overflow и ручное обрезание запрещены.

## 7. Лобби

- Начальный режим — Rating.
- Hero в Rating: аватар, рейтинг/RP и play-баланс выровнены по одной вертикальной сетке.
- Hero в Cash: идентичность, cash-баланс, две равные кнопки `Пополнить` и `Вывести` на всю строку.
- Daily Bonus показывается только в Rating и только по server state.
- Cash и Rating не смешивают единицы, терминологию или CTA.
- В каждой секции одна смысловая задача; декоративные описания не должны занимать место игрового списка.

## 8. Игровой стол

- Стол масштабируется внутри безопасной области и не выходит за viewport.
- Места игроков привязаны к краю стола, но полностью остаются в viewport.
- Карты читаемы, сохраняют стандартную пропорцию и не растягиваются по одной оси.
- Банк, блайнды и служебные подписи имеют низкий визуальный контраст.
- Активный ход, лучшие пять карт и победитель — единственные состояния с усиленным акцентом.
- Левое и правое меню используют одинаковую геометрию grouped-list и toolbar-кнопок.
- История раздач — только текущая table session; серверные debug events не выдаются за историю рук.

## 9. Motion

| Сценарий | Длительность | Easing |
|---|---:|---|
| Press feedback | 90–120 ms | ease-out |
| Pill movement | 240–280 ms | cubic-bezier(.22,.72,.18,1) |
| Sheet enter/exit | 300–360 ms | cubic-bezier(.22,.72,.18,1) |
| Success counter | 500–700 ms | ease-out |
| Toast | 180 in / 160 out | ease-out |

При `prefers-reduced-motion: reduce` трансформации отключаются, но конечные состояния сохраняются.

## 10. Accessibility и interaction contract

- Все icon-only кнопки имеют `aria-label`.
- Focus-visible не убирается; он рисуется цветом `--weez-accent`.
- Disabled-элемент не реагирует как активный.
- Цвет не является единственным способом показать статус.
- Минимальный контраст основного текста 4.5:1.
- Любая финансовая операция имеет pending, success и error state без двойного submit.

## 11. Запрещённые практики

- Новый поздний override-блок с датой вместо исправления источника.
- `!important` в новом компоненте без documented migration reason.
- Хардкод цвета Telegram-темы внутри компонента.
- CSS/Unicode-стрелки, крестики и системные значки вместо утверждённого asset.
- Несколько scroll-контейнеров в одном sheet.
- `transition: all`.
- Hover как обязательное состояние в mobile UI.
- Текстовый debug/status overlay поверх игрового стола.

## 12. Definition of done для UI

Изменение не считается завершённым без проверки:

1. 390×844 и 430×932.
2. Telegram dark theme и ещё одна отличающаяся палитра.
3. iOS safe areas.
4. Scroll до начала и конца страницы.
5. Открытие/закрытие каждого sheet.
6. Появление/скрытие клавиатуры в deposit и withdrawal.
7. Press → drag-out → cancel на строках.
8. Значения баланса: 0, 999.99, 9 999.99, 999 999.
9. Console без uncaught errors.
10. Скриншот до/после и ручная проверка на устройстве Telegram перед продом.

## 13. Технический долг миграции

Интерфейс всё ещё загружает исторические `styles.css`, `lobby-qa.css` и `telegram-ui-kit-overrides.css`. В них много повторных селекторов и `!important`. Новые компоненты добавляются только в финальный `weez-design-system-v2.css`; при переносе компонента соответствующие legacy-правила удаляются, а не остаются вторым источником поведения.

Первым перенесён игровой chrome: toolbar, felt, служебные подписи, action controls, левое меню и правый info drawer. Совпадающий legacy-блок удалён из `telegram-ui-kit-overrides.css`. Архитектурный тест фиксирует порядок подключения и запрещает рост legacy-файлов/`!important` сверх текущего бюджета. Это промежуточная защита, а не завершение миграции.

Финальная цель — один token layer, один primitives layer и экранные стили без каскада датированных override-блоков. Следующие компоненты переносятся по одному после визуальной проверки: cashier sheets, lobby/profile cards, tournaments/private tables, затем table seats/cards/action states.


## 14. Проверка интерфейса 17 октября 2026

- В `public/ui-runtime.js` общий press feedback (110 ms), отмена при drag/scroll, focus trap,
  восстановление фокуса и отменяемое закрытие sheets. Нативный click активирует навигацию;
  собственные pointerup-переходы и искусственная пружина страницы удалены.
- `ui-state` — первый CSS layer: его important-правила владеют `[hidden]`, disabled,
  pressed, reduced motion и drag. `weez-rows`, `weez-sheets`, `weez-game` владеют важными
  свойствами мигрированных компонентов: layered important имеет приоритет над старым
  unlayered important. Обычные стили полностью перенесённых списков столов и профиля
  остаются unlayered; соответствующие legacy-селекторы удалены. Новые свойства не надо
  добавлять в старые файлы или компенсировать увеличением специфичности.
- `--app-height` использует `viewportStableHeight`; нестабильные события свайпа игнорируются.
  `--app-safe-*` объединяет `max(env, Telegram safeAreaInset)` и дополнительный
  `contentSafeAreaInset`. В iOS Telegram отступ собственных fullscreen-кнопок не включает
  status bar: [реализация Telegram](https://github.com/TelegramMessenger/Telegram-iOS/blob/master/submodules/WebUI/Sources/WebAppController.swift).
- Chromium: 320×740, 390×844, 430×932; главная, конец страницы, профиль, турниры, меню,
  документы. Горизонтальный overflow 0; нижняя навигация имеет одинаковые координаты до
  и после scroll (390×844: x=12, y=764, 366×68; 430×932: x=12, y=852, 406×68).
- Отдельно проверены светлая палитра, вход за стол, игровое меню, drag-cancel на сегменте,
  закрытие документа свайпом и повторное открытие без остаточного смещения, Tab внутри
  диалога, immediate close при reduced motion. Вызовы событий SDK с system top=44,
  content top=56 и bottom=34 дали padding-top=116 и нижнюю границу nav=798 при высоте844.
- Снимки до/после находятся в локальном игнорируемом `output/playwright/`.
  `tests/ui-runtime.test.js` проверяет стабильную высоту, сумму safe insets, отмену клика,
  disabled и гонку повторного открытия sheet; CSS budgets уменьшены после удаления legacy.
- Это браузерная проверка. Настоящие клавиатуры, жесты WebView и финальная приёмка на
  физических iOS/Android в Telegram остаются отдельной проверкой; идеальное совпадение
  с native UI не подтверждено. Cashier проверяется как интерфейс; платежи не подключены.
