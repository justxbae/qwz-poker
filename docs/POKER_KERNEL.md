# Hold’em: интеграция и сравнение, 17.10.2026

## Результат первого этапа

Подключён **PokerInfra Poker Kernel для обработки ходов Texas Hold’em**.
Omaha не подключается по решению владельца. Инфраструктура, игроки, кошельки,
интерфейс и турниры остаются в Weez. Внешнего игрового сервиса нет.

Это **частичная интеграция**, а не полная замена движка. Kernel проверяет ход,
меняет ставки/стек через свои обработчики и выбирает следующего игрока. Адаптер
добавляет ограничения повторного рейза и передаёт серверу признак конца круга.
Weez продолжает раздавать проверяемую колоду, открывать улицы, считать боковые
банки, возвраты, рейк, выплаты и сохранять историю. Отдельного состояния Kernel,
которое могло бы разойтись со снимком стола, нет.

Считать проект готовым к денежному запуску по этому этапу нельзя. Ниже отделены
проверенные возможности от незавершённых требований онлайн-комнаты.

Источник — `tests/poker-lifecycle.test.js`. Это проверки независимых инвариантов,
а не исчерпывающая проверка всех возможных последовательностей действий.

**Вывод:** текущий адаптированный вариант в проверенных случаях лучше прежнего.
Улучшение дали и Kernel, и наши дополнительные проверки/исправления. Сам по себе
немодифицированный Kernel не оказался надёжнее нашей денежной части: его
`PotManager` на взносах 20 (fold), 50 и 100 создаёт банки на 190 вместо 170.
Ошибку воспроизводит тест. Поэтому этот код выплат не используется.

## Чего ещё не хватает или что нужно закрыть

### До признания онлайн-комнаты готовой

1. **Вход и возврат относительно блайндов.** Нет завершённой политики wait-for-BB,
   entry blind и учёта пропущенных блайндов в cash. Сейчас игрок получает карты
   со следующей руки. Возврат после sit out/rejoin ещё может обходить оплату
   блайндов. Переходы 3→2
   и выходы BTN/SB/BB отдельно исправлены; это не заменяет учёт пропущенных блайндов.
2. **Остановка/восстановление процесса.** Нужны graceful shutdown, прекращение
   приёма новых ходов, завершение сохранения, рестарт посреди ставки/runout/выплаты.
   Сейчас нормализация после рестарта выдаёт новый таймер, но не заменяет эти проверки.
3. **Сбой хранилища и конкуренция.** Проверить реальными PG/Redis повтор после
   неизвестного результата commit, утрату Redis lock и rollback. Продление lock
   не контролирует результат 0; несколько писателей пока не поддерживаются.
4. **Мобильная сеть.** Нужны серии раздач с уходом/возвратом,
   потерей SSE, двойными кликами, задержанными запросами и фоновым Telegram.
   Проверка вычислительных сценариев не заменяет сетевую приёмку.

### Исправлено в клиенте 17.10

- Подтверждение ставки и отложенный pre-action привязаны к исходному ходу;
  предвыбор не переносится на следующую руку. Show/muck привязан к своему окну.
- Окно ввода суммы закрывается при смене хода. Старый ответ/повтор запроса не
  откатывает показанное состояние стола к прошлой revision.
- Максимальный рейз учитывает сумму, уже необходимую для колла. Неполный all-in
  остаётся допустимым; кнопка короткого колла показывает фактически вносимый стек.
- Кнопка OK в окне бай-ина раньше перехватывалась pointer capture перетаскивания.
  Захват теперь начинается после реального движения, кнопки/поля исключены.
  В реальном браузере до исправления вход не выполнялся, после — выполнен.
  Посадка и ручной check прошли через UI с HTTP 200, ошибок JavaScript не было.
- При закрытии ожидающего стола клиент возвращается в лобби; при выходе во время
  руки показано предупреждение о сохранении уже внесённых ставок в банке.
- Отложенный sit out больше не превращает завершённую all-in руку в folded
  и не скрывает обязательное раскрытие карт. Это отдельный регрессионный тест.

### Полезные возможности следующего этапа

- Timebank: +15 секунд описаны как резерв в спецификации, собственного
  серверного баланса timebank пока нет.
- Предвыбор check/fold/call-any есть **в клиенте**; закрытая вкладка его не выполнит.
  Серверные pre-actions Kernel сейчас не включены.
- Очередь на занятый стол, auto-top-up, wait-for-BB UI и leave-next-BB пока не готовы.
- Run it twice, straddle и rabbit hunt не включены; это отдельные правила продукта,
  а не обязательное условие корректного базового Hold’em.
- Раскладка 7–9 мест требует отдельной проверки интерфейса перед открытием в API.

## Версия, документация и лицензия

Исходники закреплены на коммите
[`d61417489da92a9535cd84c3a23c69f975e7056f`](https://github.com/pokerinfra/poker-kernel/tree/d61417489da92a9535cd84c3a23c69f975e7056f).
Состав и локальные изменения описаны в `vendor/poker-kernel/README.md`.
Приложению не нужен новый build step: исполняемые CommonJS-файлы сохранены рядом
с исходниками, инструкцией пересборки и лицензией.

В [публичном репозитории Poker Kernel](https://github.com/pokerinfra/poker-kernel)
нет обещанного набора из 516 тестов: есть заявление в README, исходники и инструкции.
Заявление не считается результатом наших проверок. Общие правила повторного
открытия ставок сверены с
[официальным правилом Poker TDA 49](https://www.pokertda.com/view-poker-tda-rules/).
TDA используется для проверки этих правил NLH, не как замена cash house rules Weez.

Код имеет SPDX `AGPL-3.0-only`; исходники и уведомления включены в экспорт релиза.
Выбор AGPL-условий либо коммерческой лицензии авторов для закрытого публичного
продукта нужно разрешить до публикации. Коммерческая лицензия этой интеграцией
не получена. Изменения локальные; Render и production не обновлялись.
