# Состояние проекта после уборки

Проверено локально 2026-10-16. Этот документ помогает начать работу без истории
чата. Продуктовые правила находятся в `MASTER_SPEC.md`, навигация — в [README](README.md).

## Выполнено

- 16 исторических файлов перенесены в `archive/`: прежние задания для чатов,
  дизайнерские ТЗ, аудиты и PDF-экспорты. Содержимое сохранено, пути обновлены.
- `AGENTS.md` сокращён и исправлен по текущему коду: Render включает real-money,
  курс Stars уже 0.01, staging представлен отдельным blueprint.
  `CLAUDE.md` ссылается на общие правила вместо второй расходящейся копии.
- Добавлены входной README, карта документов и инструкция развёртывания.
- Личные файлы, Word-документы и локальные фотореференсы сохранены в игнорируемой
  `.local/`: `personal/`, `reference-documents/`, `design-references/`.
  Это пользовательские материалы, а не временные файлы для удаления.
- Уточнены исключения Git: варианты `.env`, локальные материалы, результаты и coverage.
- Экспорт релиза теперь содержит обязательный `vendor/pokersolver`, его package
  boundary и MIT-лицензию. Прежде экспорт не мог загрузить showdown evaluator.
  Отсутствующие обязательные файлы больше не пропускаются молча.
- Docker использует lockfile и копирует только необходимые серверу файлы.
- Два загрузчика `.env` объединены в `server/env.js`. Явная пустая переменная
  окружения теперь сохраняется: локальный файл не может заново включить подключение.
- HTTP-тесты по умолчанию отключают унаследованные PostgreSQL/Redis и реальные
  уведомления владельцу; тест отказа запуска ограничен таймаутом вместо зависания.
- Добавлены проверки приоритета настроек и работоспособности экспортированного evaluator.

## Проверки

- До изменений: 126 тестов, 117 успешных, 9 пропущенных, ошибок и отмен нет.
- После изменений: `npm test` — 129 тестов, 120 успешных, 9 пропущенных,
  ошибок и отмен нет. Локальная проверка выполнена на Node.js 22.22.3;
  CI настроен на Node.js 20 и локально не воспроизводился отдельно.
- HTTP-suite отдельно прошёл с намеренно неверными унаследованными адресами
  PostgreSQL/Redis: обычные проверки используют память.
- `npm run release:clean` создаёт экспорт. Сервер из экспорта запущен в demo,
  `/api/health`, HTML, JS, финальный CSS и SVG ответили HTTP 200.
  Для smoke-проверки использованы уже установленные зависимости через временную
  ссылку, удалённую после проверки; отдельная установка из сети не выполнялась.
- Локальные ссылки входной документации и статические ссылки проверены.
- Инфраструктурные и платёжные E2E не запускались: отдельные тестовые сервисы
  не подключались. Docker-образ не собирался: Docker локально отсутствует.
- Production-конфигурация, игровые правила, платёжный курс и CSS не изменены.
  Изменения локальные; отправки в Git и развёртывания не выполнялись.

## Оставшийся технический долг

Структура и вход в проект упорядочены. Внутри крупных файлов всё ещё есть
накопленные слои; уборка репозитория не означает завершённый рефакторинг.

| Область | Проверенный размер | Следующая задача |
| --- | ---: | --- |
| `server/index.js` | около 7 300 строк | Выносить HTTP-домены и служебные функции по одному, сохраняя API |
| `server/db.js` | около 4 400 строк | Разделять хранилище по доменам с паритетом PostgreSQL/memory |
| `public/app.js` | около 7 600 строк | Выделять состояния и отображение lobby, cashier, table, profile |
| Четыре CSS-файла | 30 687 строк, 9 502 `!important` | Убирать старые правила по компонентам после сравнения внешнего вида |

Файлы дизайна в `archive/design/figma/`, текущие планы в `docs/` и `vendor/pokersolver` имеют
назначение. Не удалять их только из-за размера или старого названия.
Префиксы `qwz_*`, совместимые платёжные payload и домен сервиса — действующие
контракты; переименование требует отдельной миграции.

## Очередь дальнейшей уборки

1. Зафиксировать внешний вид текущего клиента: lobby, cashier, table, profile,
   sheets; светлая/тёмная тема и мобильные размеры. Это основа проверки CSS.
2. Выбрать один компонент, собрать его правила в финальном stylesheet, удалить
   подтверждённо заменённые правила и уменьшить соответствующий budget в тесте.
3. Выделить один независимый HTTP-домен из `server/index.js`; сохранить маршруты,
   авторизацию, статусы ответов и порядок финансовых операций. Выполнить его тесты.
4. Аналогично разделять `public/app.js` и `server/db.js` небольшими законченными
   изменениями. Деньги и игровую механику не менять одновременно с переносом кода.

Для каждого этапа: понятная граница изменения, проверка прежнего поведения,
обновление затронутого контракта при необходимости. Продуктовая очередь отдельно
ведётся в [TECH_ROADMAP](TECH_ROADMAP.md).
