# QWZ Poker: ТЗ на UI/UX-дизайн для Claude

## 1. Что нужно сделать

Нужно спроектировать полный UI/UX Telegram Mini App для покерного клуба **QWZ Poker**.

QWZ Poker - это покерный продукт внутри Telegram: пользователь открывает бота, сразу попадает в Mini App, может выбрать формат игры, пополнить баланс, сесть за стол и играть в Texas Hold'em без перехода в отдельное приложение.

Дизайн должен выглядеть не как казино-сайт и не как обычный мобильный веб-сервис, а как **нативная, аккуратная часть Telegram**. У пользователя должно возникать ощущение: "это покерный клуб, который органично встроен в Telegram".

На текущем этапе дизайн проектируется для mobile-first Mini App. Основное устройство - iPhone внутри Telegram WebView. Также нужно предусмотреть адаптацию для Android и небольшого desktop-view Telegram.

## 2. Главная продуктовая идея

**QWZ Poker - первый нативный покерный клуб внутри Telegram.**

Пользователь не должен:

- скачивать отдельное приложение;
- проходить длинную регистрацию;
- разбираться в сложной навигации;
- искать, где начать играть.

Пользователь должен понять путь за несколько секунд:

1. Открыл Mini App.
2. Выбрал: игра на реальные chips или бесплатная игра на фантики.
3. Выбрал лимит или турнир.
4. Пополнил баланс, если это требуется.
5. Сел за стол и начал играть.

## 3. Важно: статус продукта

### Уже реализовано или находится в активной разработке

- Telegram Mini App.
- Авторизация через Telegram-профиль.
- Лобби, список столов, касса, профиль, турниры.
- Texas Hold'em cash tables, до 6 игроков.
- Buy-in перед посадкой за стол.
- Игровой стол: карты, банк, блайнды, статусы игроков, действия fold/check/call/bet/raise/all-in.
- Пополнение через Telegram Stars.
- Подготовка пополнения через TON и USDT TRC20.
- История операций.
- Provably fair / честность раздач.
- Админская часть, которая не относится к публичному пользовательскому дизайну.

### Нужно предусмотреть в дизайне сейчас, даже если будет разработано позже

- Два режима игры: **реальные chips** и **play chips / фантики**.
- Ежедневная выдача бесплатных play chips раз в 24 часа.
- Бонусы, wagering/отыгрыш и bonus balance.
- Реферальная система.
- Уровень игрока как статус, без прямого игрового преимущества.
- Достижения.
- Турниры.
- Вывод средств.
- Страница/модалка проверки честности раздачи.
- Уведомления и центр поддержки.

## 4. Целевая аудитория

Основной пользователь:

- уже использует Telegram каждый день;
- может знать покер или пробовать впервые;
- приходит по рекомендации друга, из канала или рекламы;
- ожидает быстрый старт без лишних экранов;
- чувствителен к доверию: деньги, честность раздач, понятный баланс и вывод.

Есть два важных типа пользователей:

1. **Новичок** - хочет быстро попробовать бесплатно и понять игру.
2. **Регуляр / платящий игрок** - хочет быстро найти подходящий стол, видеть деньги, лимиты, историю и доверять системе.

## 5. Стиль и визуальное направление

### Основное направление

Интерфейс должен быть максимально близким по логике и ощущению к Telegram:

- нативная структура Telegram Mini App;
- спокойный, чистый, функциональный интерфейс;
- familiar navigation;
- правильные отступы, радиусы, высоты строк и кнопок;
- системное ощущение, а не рекламные блоки и не тяжелый casino-gloss.

Референс по атмосфере: Telegram Settings / Telegram Wallet / Tribute Mini App. Не нужно буквально копировать бренд чужого продукта, но нужно взять их аккуратность, ясную навигацию и Telegram-native поведение.

### Цветовая палитра

Нужно проектировать минимум dark theme как основной сценарий. Светлую тему можно предусмотреть токенами, но основной итоговый набор экранов сначала сделать в dark.

Рекомендуемая основа для dark theme:

- Background: однотонный Telegram-like тёмный фон, без декоративных градиентов и узоров.
- Secondary surface: немного светлее фона для списков/секций.
- Primary accent: Telegram blue для действий, выбранных состояний и активной навигации.
- Success: зелёный только для успеха, выигрыша, positive balance/action.
- Warning: жёлтый/amber только для ожидания, бонусов, pending.
- Danger: красный только для fold, ошибок, списаний или risky action.
- Text primary: почти белый, но не ослепляющий.
- Text secondary: приглушённый Telegram-grey.

Важно:

- не делать весь продукт однотонно-синим;
- не делать премиум-casino палитру из золота и чёрного;
- не использовать лишние свечения, стеклянные эффекты, градиентные орбы или декоративные узоры;
- весь интерфейс должен визуально совпадать с тёмной верхней частью Telegram Mini App.

### Шрифт

Использовать практичную Telegram/iOS-like типографику: системный sans-serif, близкий к SF Pro / Telegram UI.

Правила:

- не делать большинство надписей жирными;
- bold использовать для баланса, суммы выигрыша, primary headline и ключевого CTA;
- вторичную информацию держать спокойной и компактной;
- цифры баланса, ставок и банка должны хорошо сканироваться.

### Компоненты

Нужна дизайн-система с вариантами:

- primary / secondary / danger / disabled buttons;
- list row как в Telegram settings;
- segmented controls;
- tabs / bottom navigation;
- status badges;
- balance item;
- table list row;
- input / slider / amount selector;
- modal / bottom sheet;
- toast / alert;
- player seat;
- poker card;
- chip stack;
- empty / loading / error states.

Кнопки и строки должны иметь telegram-like размеры и радиусы. Не создавать огромные маркетинговые карточки там, где лучше выглядит обычный список.

## 6. Навигация Mini App

Основная нижняя навигация:

1. **Главная**
2. **Столы**
3. **Касса**
4. **Турниры**
5. Отдельная круглая **аватарка профиля** справа, визуально отделённая от основной панели

Требования:

- нижняя панель плавающая, достаточно широкая, с одним чистым слоем фона;
- активная вкладка визуально выделяется одним аккуратным состоянием, без двойных обводок;
- profile avatar не должна иметь зелёную обводку при hover/press;
- анимация переключения вкладок небольшая и нативная, как в Telegram;
- при переходе на другую вкладку пользователь попадает в начало контента;
- long press и double tap не должны создавать странные состояния или выделение текста.

Во время игры нижняя навигация лобби скрывается. Игровой экран должен полностью погружать пользователя в стол.

## 7. Архитектура экранов

Нужно спроектировать следующие экраны и состояния.

---

## Экран 1. Первый запуск / Главная

### Цель

Пользователь впервые открыл бота и должен моментально понять:

- что это покерный клуб в Telegram;
- можно ли играть бесплатно;
- где начать игру;
- какой у него баланс;
- что для real mode потребуется пополнение.

### Содержание

- Telegram-профиль пользователя: аватар, имя, username.
- Короткий product hook, без агрессивной рекламы:
  - например: `Poker club inside Telegram` / `Покер прямо в Telegram`.
- Переключатель режимов:
  - `На chips` / `На фантики`.
- Блок текущих балансов:
  - `Real chips`;
  - `Play chips`;
  - в будущем `Bonus chips`.
- Основное действие:
  - если выбран real mode и денег нет: `Пополнить и играть`;
  - если real balance есть: `Играть`;
  - если play mode: `Играть бесплатно`.
- Быстрый выбор лимита: например `25/50`, `50/100`, `100/200`.
- Число активных столов / онлайн игроков, если данные доступны.
- Небольшой entry point для турниров.

### Первый вход для новичка

Для пользователя с нулевым балансом не нужно показывать тупик. Он должен сразу видеть:

- бесплатный режим;
- ежедневные фантики;
- понятную кнопку real deposit, если он хочет играть на деньги.

### Состояния

- real balance = 0;
- play chips доступны для claim;
- play chips уже получены сегодня, показан таймер до следующей выдачи;
- есть активный стол: CTA `Вернуться за стол`;
- есть активный бонус / стартовое предложение.

---

## Экран 2. Выбор режима игры

Можно оформить как modal/bottom sheet при первом входе или как clear segmented switch на главной.

### Режим `На фантики`

- Бесплатные play chips.
- Не выводятся.
- Можно получить фиксированную сумму раз в 24 часа.
- Предназначены для обучения и игры без риска.

### Режим `На chips`

- Баланс можно пополнять.
- В будущем возможен вывод.
- Применяются реальные лимиты и история операций.

Важно: визуально нельзя путать эти балансы. Пользователь всегда должен понимать, на каком типе chips он сейчас играет.

---

## Экран 3. Столы / Lobby Tables

### Цель

Быстро выбрать открытый стол, лимит и сесть играть.

### Содержание

- Переключатель режима: `Real` / `Play`.
- Фильтр по лимитам.
- Строки открытых столов:
  - название/лимит;
  - число игроков `3/6`;
  - min buy-in;
  - свободные места;
  - статус: активная игра / ожидание;
  - CTA `Сесть`.
- Отдельная возможность создать приватный стол для друзей, но не делать её главным сценарием.

### Состояния

- открытых столов нет;
- стол заполнен;
- недостаточно баланса;
- у пользователя уже есть активный стол;
- play/real table визуально различимы;
- стол с ожиданием игроков.

---

## Экран 4. Buy-in / Вход за стол

### Цель

Перед посадкой пользователь выбирает стек и понимает, сколько chips перемещается за стол.

### Содержание

- Название режима и лимита: например `Texas Hold'em 25/50`.
- Тип баланса: `Real chips` или `Play chips`.
- Доступный баланс.
- Min/max buy-in.
- Поле ручного ввода суммы.
- Ползунок выбора buy-in.
- Быстрые значения `Мин.`, `50%`, `Макс.` или аналогично.
- Опциональный чекбокс/переключатель `Auto rebuy` в будущем.
- CTA `Сесть за стол`.

### UX-условия

- При появлении клавиатуры ничего не перекрывается и не меняет состояние самопроизвольно.
- Значение можно удобно вводить пальцем.
- Нельзя перепутать play и real chips.
- Если денег недостаточно, вместо ошибки предложить перейти в кассу или бесплатный режим.

---

## Экран 5. Игровой стол

### Цель

Это самый важный экран. Он должен быть лаконичным, быстрым и погружающим.

### Общая структура

- Верхняя строка:
  - выход/меню;
  - номер/название стола;
  - дополнительная информация;
  - invite/info при необходимости.
- Игровой стол фиксирован по размеру и не скачет при смене ставок, действий или карт.
- В центре:
  - blinds (`25/50`);
  - pot / bank;
  - community cards;
  - chips, которые собираются в банк;
  - короткие статусы улицы (`Flop`, `Turn`, `River`) в свободной зоне, не поверх карт.
- Игроки по краям стола:
  - avatar;
  - nickname;
  - stack;
  - status badge `D`, `SB`, `BB`, `Fold`, `All-in`, `Ход`;
  - закрытые или открытые карты.
- Нижняя зона действий:
  - Fold;
  - Check / Call;
  - Bet / Raise;
  - slider и quick amount presets при выборе ставки;
  - сумма и confirm button.

### Правила визуального поведения

- Pot никогда не перекрывается картами.
- Nickname и balance не перекрываются badges.
- Active player подсвечен спокойно, без быстрого агрессивного мигания.
- Основные действия различаются по цветам:
  - Fold - danger;
  - Check/Call - neutral/positive;
  - Bet/Raise - action accent.
- При all-in статус заметен, но не ломает раскладку.

### Анимации игрового процесса

Нужно заложить продуманные animation states:

- объявление начала первой раздачи;
- назначение Dealer / SB / BB;
- раздача карманных карт;
- внесение блайндов;
- после окончания раунда ставок: chips игроков перемещаются в центр стола, будто дилер собрал их в банк;
- открытие flop / turn / river с небольшими паузами;
- выигрыш банка: chips перемещаются победителю;
- fold;
- all-in;
- переход между руками;
- уход/посадка игрока.

Всё должно происходить размеренно, без резких скачков. Анимации не должны замедлять игру или блокировать действие пользователя дольше необходимого.

### Состояния

- waiting for second player;
- table intro;
- preflop;
- flop;
- turn;
- river;
- all-in runout;
- showdown;
- winner payout;
- player sit out;
- reconnect / плохой интернет;
- игрок наблюдает, но не сидит за столом;
- недостаточно chips / rebuy.

---

## Экран 6. Касса / Wallet

### Цель

Пользователь ясно понимает свой баланс, способы пополнения, будущий вывод и историю операций.

### Балансы

Необходимо показать три типа средств:

1. `Real chips` - купленные/выводимые средства.
2. `Bonus chips` - бонусные средства, которые требуют отыгрыша.
3. `Play chips` - бесплатные фантики, не выводятся.

### Пополнение

Нужен сценарий:

1. Пользователь вводит сумму в рублях.
2. Видит, сколько получит chips.
3. Выбирает способ оплаты:
   - Telegram Stars - активный;
   - TON - будет активирован;
   - USDT TRC20 - будет активирован.
4. Нажимает `Пополнить`.

В дизайне нужны:

- поле ₽;
- быстрые ₽-пресеты;
- quote в chips;
- quote стоимости по выбранному методу;
- список платежных методов;
- pending/success/error payment states;
- история пополнений.

### Вывод

Вывод проектировать как реальную будущую функцию:

- доступно к выводу;
- сумма вывода;
- метод: TON / USDT / RUB partner / Stars-Gifts, если будет разрешено;
- комиссия;
- сумма к получению;
- адрес/реквизиты;
- статус заявки:
  - pending;
  - on review;
  - approved;
  - paid;
  - rejected/refunded.

Важно: bonus chips и play chips не должны выглядеть доступными к выводу.

---

## Экран 7. Daily Play Chips / Бесплатная игра

### Цель

Позволить новичку играть без депозита и повысить retention.

### Содержание

- Баланс play chips.
- CTA `Получить ежедневные фантики`.
- Сумма ежедневной выдачи.
- После получения - таймер до следующей выдачи.
- Кнопка `Перейти к бесплатным столам`.
- Текст одной строкой: `Play chips не выводятся и используются только для бесплатной игры`.

### Важно

- Бесплатный режим не должен ощущаться “урезанным мусорным режимом”.
- Но нельзя визуально смешивать его с real-money mode.

---

## Экран 8. Турниры

### Цель

Пользователь видит предстоящие и текущие турниры и может зарегистрироваться.

### Список турниров

- Название.
- Формат: freeroll / regular / special.
- Тип баланса: real или play.
- Buy-in.
- Prize pool.
- Время старта.
- Количество регистраций.
- Status: registration / running / finished.
- CTA `Регистрация`.

### Будущие сценарии

- freerolls;
- weekly events;
- major tournaments;
- leaderboards;
- результаты турниров.

---

## Экран 9. Профиль

### Содержание

- Avatar из Telegram.
- Username / имя.
- Уровень игрока как статус.
- Real balance / Bonus balance / Play balance.
- Число сыгранных рук.
- Количество столов / турниров.
- Достижения.
- Активные бонусы и прогресс wagering.
- Реферальная ссылка / приглашения.
- История операций.
- Responsible gaming / лимиты / поддержка в будущем.

### Уровень

Уровень не даёт преимущества в игре. Он показывает только опыт и статус пользователя, например:

- Newcomer;
- Regular;
- Grinder;
- Veteran.

---

## Экран 10. Бонусы и предложения

Нужно предусмотреть отдельный раздел или modal/sheet из главной/кассы.

### Будущие бонусы

- welcome bonus на первый депозит;
- reload bonus;
- daily/weekly missions;
- freerolls;
- referral rewards;
- achievements rewards.

### Требования

- Пользователь должен видеть:
  - сколько bonus chips получено;
  - сколько уже отыграно;
  - сколько осталось wagering;
  - срок действия;
  - что можно и нельзя вывести.
- Нельзя создавать ощущение скрытых условий.

---

## Экран 11. История рук и честность игры

### Hand History

- список сыгранных рук;
- дата/время;
- стол и лимит;
- итог руки: win/loss;
- pot;
- открытие деталей.

### Детали руки

- места игроков;
- sequence действий;
- board;
- карты, если доступны по правилам раскрытия;
- pots / side pots;
- rake;
- финальный результат.

### Provably Fair

Нужна понятная страница или bottom sheet:

- текст: `Раздача проверяема`;
- server hash;
- player hash;
- раскрытые proof-данные после руки;
- CTA `Проверить раздачу`;
- результат: `Проверка успешна`.

Это не главный экран, но важная функция доверия для серьёзного покерного продукта.

---

## Экран 12. Реферальная система

Предусмотреть будущий пользовательский сценарий:

- пригласить друга;
- копировать ссылку / отправить в Telegram;
- количество приглашённых;
- полученные награды;
- условия награды.

Дизайн не должен обещать конкретный процент, пока экономика не утверждена.

---

## 8. Системные UX-состояния

Для всех основных сценариев нужны состояния:

- loading/skeleton;
- empty;
- network error;
- payment pending;
- payment failed;
- insufficient balance;
- disabled action;
- confirmation modal для денежных действий;
- success feedback;
